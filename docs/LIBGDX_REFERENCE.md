# Заметки по стандартным подходам LibGDX

Проверено: 2026-10-05. Это исследовательская справка, а не план добавления возможностей в игру.

## Как использовать источники

Перед реализацией конкретной задачи найти соответствующий раздел, изучить доступный текст и проверить API для версии проекта. Затем объяснить подход пользователю и сделать один небольшой проверяемый шаг. Книги полезны для устройства игры, актуальная документация и исходники — для совместимости API. Общие выводы ниже не означают, что вся книга прочитана.

## Книги, просмотренные у издателя

### Mastering LibGDX Game Development — Patrick Hoey

Просмотрены оглавление главы 2 и открытые фрагменты разделов:

- [Creating and editing tile-based maps](https://subscription.packtpub.com/book/game-development/9781785289361/2/ch02lvl1sec13/creating-and-editing-tile-based-maps): автор создаёт окружение из тайлсетов через Tiled.
- [Implementing map management with spawn points and a portal system](https://subscription.packtpub.com/book/game-development/9781785289361/2/ch02lvl1sec17/implementing-map-management-with-spawn-points-and-a-portal-system): отдельный `MapManager` помогает загружать карты, получать слои и объекты; упомянуты TMX, `Screen` и `OrthogonalTiledMapRenderer`. Подробная реализация переходов в доступном фрагменте не раскрыта.

Оглавление главы 2 также разделяет загрузку ресурсов, камеру, карты, персонажа и ввод. Полный текст выбранных разделов у издателя требует входа/доступа; прочитаны только открытые фрагменты.

### Libgdx Cross-platform Game Development Cookbook

Просмотрены оглавление и открытые фрагменты главы 9:

- [Creating maps with Tiled and loading them into Libgdx](https://subscription.packtpub.com/book/game-development/9781783287291/9): построение уровня в Tiled, загрузка и отрисовка в игровом цикле.
- [Adding and querying map metadata](https://subscription.packtpub.com/book/game-development/9781783287291/9/ch09lvl1sec68/adding-and-querying-map-metadata): карта содержит объекты и свойства для событий, сущностей, начальной позиции и выхода. Код после загрузки читает эти данные и создаёт игровые сущности.

Полный текст рецептов требует доступа. По оглавлению для дальнейшего изучения подходят главы о камере/viewport, ресурсах, аудио, физике и профилировании; их полное содержание сейчас не изучено.

## Что проверено в официальной документации

- [Tile maps](https://libgdx.com/wiki/graphics/2d/tile-maps): `TiledMap` содержит слои, клетки ссылаются на тайлы; `OrthogonalTiledMapRenderer` рисует ортогональную карту. Можно отдельно рисовать фоновые слои, персонажей и передние слои. Масштаб мира задаётся через `unitScale`. Карта может загружаться через `TmxMapLoader` и `AssetManager`; ресурсы требуют корректного освобождения.
- [Orthographic camera](https://libgdx.com/wiki/graphics/2d/orthographic-camera): камера задаёт видимую область мира, положение и масштаб. Координаты мира и размер окна следует различать.
- [Managing your assets](https://libgdx.com/wiki/managing-your-assets): `AssetManager` управляет загрузкой ресурсов и их зависимостями; ресурсы имеют жизненный цикл, а OpenGL-зависимая работа выполняется на потоке рендера.

Важно: документация `Tile maps` предупреждает, что бесконечные TMX-карты не поддерживаются. Нельзя обещать автоматическую загрузку бесконечного мира только потому, что его умеет редактировать Tiled. Для TMJ/JSON и конкретной версии поддержку проверять отдельно. Возможный самостоятельный менеджер чанков — дополнительная разработка, а не готовая функция редактора.

## Вывод для будущего обсуждения мира

Для первого диалога изучен [Scene2d.ui](https://libgdx.com/wiki/graphics/2d/scene2d/scene2d-ui): интерфейс отделяется от мира, действие кнопки меняет состояние. В Swing это отдельная `DialoguePanel`, рисуемая поверх карты без сдвига камеры, и состояние `dialogueActive` в игровой панели. Близость NPC проверяется в координатах мира через квадрат расстояния; разговор останавливает движение до завершения одной реплики. Попытка открыть главу 5 Mastering LibGDX у издателя вернула ошибку доступа, её содержание в этой задаче не прочитано.

Первый двор реализован в Swing по принципу камеры из [Orthographic camera](https://libgdx.com/wiki/graphics/2d/orthographic-camera): координаты игрока остаются в мире, `Camera` вычисляет видимую область и ограничивает её границами, один сдвиг применяется к фону и игроку. PNG загружается однократно. В этом эксперименте одна единица мира равна одному пикселю исходного изображения; масштаб 1:1, окно 800×556. Препятствия приблизительные прямоугольные, перекрытие игрока кронами пока не реализовано.

Для пиксельной кнопки проверен [Skin](https://libgdx.com/wiki/graphics/2d/scene2d/skin): оформление виджета отделяется от действия, используются растровый шрифт и состояния кнопки. В Swing-прототипе `PixelButton` использует состояния стандартной модели кнопки, а `PixelFont` рисует нужные шесть кириллических глифов сеткой 5×7 с целочисленным масштабом. Это маленький шрифт для надписи «Играть», не полный алфавит и не полноценный LibGDX Skin.

Для меню просмотрен [официальный пример Game/Screen](https://libgdx.com/wiki/start/simple-game-extended): меню и игровой экран разделены, переключаются через `Game`. В текущем Swing-прототипе небольшой аналог — отдельная `MenuPanel` и замена панели в `Main`; переход на LibGDX этим не выполнен.

Для двора по фото просмотрена [документация слоёв Tiled](https://doc.mapeditor.org/en/stable/manual/layers/): фон может быть Image Layer, а препятствия и точки перехода — Object Layers. Выбор первого эксперимента записан в `future-ideas/COURTYARD_BACKGROUND.md`.

Обычная основа: данные локации в редакторе → загрузчик → слои и объекты → отдельные игровые сущности → обновление состояния → камера и отрисовка. Места появления и переходы можно задавать объектами карты. Небольшая первая проверка — одна конечная карта с персонажем; затем отдельным шагом переход между двумя картами.

Это вариант, обоснованный источниками, а не утверждение, что существует единственная архитектура. ECS, физический движок, чанки и собственный формат вводятся только под конкретную задачу. Текущая игра остаётся Swing-прототипом до отдельной задачи на переход.
